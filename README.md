# SHAPE - From Narrative Clinical Pathways to Computable FHIR PlanDefinitions

SHAPE is a pipeline for the automatic transformation of narrative clinical pathways into executable **HL7 FHIR R5 PlanDefinition** resources.

The pipeline combines Large Language Models (LLMs), Retrieval-Augmented Generation (RAG), ontology-based semantic grounding, and deterministic FHIR encoding to extract clinical workflows, identify healthcare activities, infer parameters, and generate structured FHIR representations.

### Source Code (`src`)

The source code implementing the SHAPE pipeline is located in the `src` folder.

- **`main.py`**
  - Entry point of the SHAPE pipeline.

- **`model`**
  - Contains all the model classes used throughout the pipeline.

- **`routines`**
  - Contains utility scripts for initializing and populating external resources:
    - SNOMED CT Qdrant collection creation and population.
    - ActivityDefinition Qdrant collection creation and population.

- **`resources`**
  - Contains static resources required by the pipeline:
    - configuration files;
    - LLM prompts;
    - FHIR templates;
    - other pipeline resources.

- **`sources`**
  - Contains classes implementing connections with external services:
    - Ollama interface;
    - Qdrant interface.

- **`stages`**
  - Contains the implementation of the different SHAPE pipeline stages.

- **`utils`**
  - Contains general-purpose utility methods used across the project.

## Dataset

The `dataset` folder contains all data required for running and evaluating SHAPE.

It includes:

- **Narrative clinical pathways**
  - Input clinical pathway descriptions used as input for the pipeline.

- **ActivityDefinition resources**
  - Reference HL7 FHIR R5 ActivityDefinition resources used for semantic grounding.

- **Ground truth**
  - Manually validated reference data:
    - FHIR R5 PlanDefinition resources.
    - Ground truth model elements used for evaluation.

# Output

The `output` folder contains the artifacts generated by SHAPE when executed according to the experimental setup described in the paper.

For each narrative clinical pathway, the folder contains the outputs generated using the five evaluated LLM configurations.

The generated artifacts include:

- generated FHIR PlanDefinition resources;
- intermediate representations produced by the different pipeline stages;
- additional outputs required for analysis.

# Research Questions

The evaluation of SHAPE is structured around the following research questions.

## RQ1

**Can SHAPE accurately reconstruct the logical structure of a narrative clinical pathway?**

This research question evaluates the ability of SHAPE to extract the workflow structure from narrative clinical pathways, including:

- clinical actions;
- action relationships;
- temporal constraints;
- execution conditions.

---

## RQ2

**How accurately does SHAPE semantically ground the extracted clinical knowledge?**

This research question evaluates the semantic grounding capabilities of SHAPE, including:

- identifying appropriate ActivityDefinition resources;
- inferring clinical parameters.
- mapping extracted clinical parameters to standardized healthcare concepts;

---

## RQ3

**Does SHAPE generate structurally valid and semantically correct FHIR PlanDefinition resources?**

This research question evaluates the final FHIR generation stage, assessing:

- structural correctness of generated PlanDefinition resources;
- semantic consistency of generated elements;
- correctness of encoded clinical knowledge.

```bash
pip install -r requirements.txt
```

# External Services

SHAPE requires the following external services:

- Ollama
- Qdrant

Both services can be started using Docker Compose.

---

# Environment Configuration

SHAPE uses environment variables to configure external services and runtime parameters.

A template configuration file is provided:

```text
.env_example
```

Create the actual environment file by copying the template:

```bash
cp .env_example .env
```

Then update the values according to your local setup.

The `.env` file contains the configuration required by external services, including Qdrant authentication.

Example:

```env
QDRANT_API_KEY=<your-qdrant-api-key>
```

The `.env` file should not be committed to the repository.

Additional pipeline configurations (LLM models, paths, prompts, templates, and other resources) are available in:

```text
src/resources
```

---

# Starting External Services

Start Ollama and Qdrant using:

```bash
docker compose up -d
```

During the first execution, Ollama automatically downloads the required LLM models.

---

# SNOMED CT Setup

Download the desired version of SNOMED CT.

The terminology resources are required to populate the Qdrant semantic grounding collection.

After downloading SNOMED CT, configure the corresponding paths inside the SHAPE configuration files.

---

# Running SHAPE

After configuring the environment and installing the required dependencies, execute:

```bash
python -m src.main
```

The pipeline executes the complete SHAPE workflow:

1. Stage 1: Action Identification and Relationship Modeling
2. Stage 2: Clinical Activity Grounding
3. Stage 3: Clinical Parameter Resolution
4. Stage 4: FHIR Representation Generation
5. Stage 5: Deterministic PlanDefinition Construction

The generated resources are stored in the configured output directory.

---

# Running the Evaluation

After executing the pipeline, run:

```text
experiment.ipynb
```

The notebook reproduces the evaluation procedure described in the paper and computes the metrics for:

- **RQ1**: logical structure reconstruction.
- **RQ2**: semantic grounding accuracy.
- **RQ3**: FHIR PlanDefinition validity and semantic correctness.

The detailed results are available as CSV files inside:

```text
evaluation/RQ1
evaluation/RQ2
evaluation/RQ3
```
